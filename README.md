# オンチェーンゲーム設計アトラス

オンチェーンゲームの歴史を横断して、「何が発明され、何が成立せず、どこにまだ可能性が残るか」を出典付きで調べる研究サイトです。
自分の設計仮説を比べ、次に試す実験を選ぶために使います。静的サイトで動き、バックエンド・認証・課金 API は使いません。

公開サイト: https://r0ze998.github.io/onchain-game-atlas/ （main への push ごとに GitHub Actions が検査・テストして `gh-pages` ブランチへ配信）

## 起動

```sh
npm install          # 開発用の依存（js-yaml、playwright）。サイトの表示自体には不要
npm run build        # data/*.yaml を検査し site/data.generated.js を生成（エラーがあると失敗）
npm run serve        # http://127.0.0.1:8080/ で配信（依存なしの Node サーバー）
```

`site/index.html` をブラウザで直接開いても動きます（file://）。ただし研究ノートは URL（オリジン）ごとに保存されるため、
file:// と http://127.0.0.1:8080/ では別のノートになります。

## 画面

| 画面 | 内容 |
|---|---|
| 年表 `#/timeline` | 時代区分（何の制約が変わったか）と出来事。発表・テスト公開・公開・仕様変更・終了を区別。日付は資料で確認できた精度のまま |
| 索引 `#/entries` | 55 項目。7 領域・状態・オンチェーンの範囲・拡張性・ソース公開・深さで絞り込み |
| 詳細 `#/entry/<id>` | 構造（オンチェーン範囲・オフチェーン依存・管理者権限・ソース・拡張）、深掘り 11 節、比較軸、数値、出来事、つながり、未確認・矛盾、検証記録、出典 |
| 比較 `#/compare/<id,id,...>` | 2〜4 件を 7 軸で並べる。総合点やランキングはなし |
| つながり `#/graph/<id>` | 中心＋直接の関係を描く図（実線＝確認された関係、破線＝分析上の類似、点線＝概念タグ）と全関係の一覧表 |
| 問い `#/questions` | 開発時の問いから、はい寄り／いいえ寄りの事例へ |
| インサイト `#/insights` | 主張・成立条件・支持事例・反例・確信度の理由・別の説明・次の小さな実験 |
| 設計仮説 `#/hypotheses` | 5 つの具体的な設計仮説を同じ表で比較。「この実験を選ぶ」で研究ノートへ |
| 研究ノート `#/notebook` | 保存・メモ・比較セット・自分の仮説と検証記録。JSON の書き出し・読み込み |
| 出典 `#/sources`、データ品質 `#/quality`、方法と定義 `#/about` | 一次／二次、参照状態、リンク検査、未検証項目、矛盾、未確認事項 |

## データの構造と追加方法

研究データと UI は分離しています。

```
data/
  games/<id>.yaml   1 事例 1 ファイル（概要・分類・状態・日付・構造・比較軸・記事・数値・出来事・関係・未確認・矛盾・出典）
  concepts.yaml     技術・メカニクス・経済設計・基盤・思想の語彙
  eras.yaml         時代区分
  questions.yaml    問い（事例への参照つき）
  insights.yaml     インサイト（支持・反例・条件・確信度・実験）
  hypotheses.yaml   設計仮説
  linkcheck.json    リンク検査の結果（npm run linkcheck で更新）
docs/
  RESEARCH_GUIDE.md 形式と調査ルール（追加時はこれに従う）
  VERIFIER_BRIEF.md 検証役の手順
  CANDIDATES.md     調査対象の洗い出しと選定理由
  verification/     項目ごとの検証記録（詳細画面に表示）
```

追加の手順:

1. `docs/RESEARCH_GUIDE.md` の形式で `data/games/<id>.yaml` を書く。出典は `sources:` にその項目の中で定義し、各文・数値・出来事・関係から ID で参照する。
2. `npm run validate`（または `node scripts/validate.mjs --only <id>`）で検査。主な検査項目:
   参照 ID の解決（出典・項目・概念・インサイト・仮説）、日付の形式と精度（`2020` / `2020-08` / `2020-08-07`、実在しない日付と未来日付を拒否）、
   事実・主張・数値・出来事の出典の有無、到達不能な出典だけに依拠する事実（エラー）と検索要約だけに依拠する事実（警告）、
   確認された関係の出典、分析上の類似の説明、深掘りの全 11 節、列挙値、ファイル名と ID の一致、出典 URL の重複。
3. `npm run linkcheck`（任意）→ `npm run build`。
4. `npm test`（検査ロジックの単体テストと実データの検査）、`npm run test:e2e`（実ブラウザでの主要導線）。公開サイトに対しては `BASE_URL=https://r0ze998.github.io/onchain-game-atlas/ node tests/e2e.mjs`。

## 検証の方法

- 調査役（事例ごとに一次資料を探して記述）と検証役（別のエージェントが原資料を開き直し、事実・数値・引用・日付・強い表現を照合して修正し、反証を追加）を分けました。検証記録は `docs/verification/` にあり、詳細画面にも表示されます。
- 文には「事実」「当事者の主張」「分析」「未確認」のラベルがあり、出典ごとに一次／二次、公開日、参照日、参照状態（参照済み／検索要約のみ／到達不能）を記録しています。
- この調査環境では medium.com、dune.com、dappradar.com、mirror.xyz が遮断されていたため、それらに依存する数値は扱っていないか、未確認として残しています。

## 記録の指紋（内容ハッシュ）

ビルド時に、各 YAML ファイルの SHA-256 と、それらを葉とするマークル木の根（dataset root）を計算してサイトに表示します。
`npm run verify`（`node scripts/verify-integrity.mjs [期待する root]`）で、手元のデータから再計算して公開値と照合できます。
ハッシュはブロックチェーンには記録していないため、改ざん検知の手がかりであって、タイムスタンプや内容の正しさの証明ではありません。

## 研究ノートの制約

ノートはブラウザの localStorage に保存されます。別のブラウザ・端末・プライベートウィンドウとは共有されず、サイトデータの削除や
ブラウザによる自動削除で消えます。別の URL（ポート・file://）で開くと別のノートになります。定期的に JSON を書き出してください。
読み込みは「統合」（既定）または「置き換え」を選べ、形式が違う JSON は拒否します。
